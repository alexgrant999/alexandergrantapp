SETTING THE FIELDS OVER THE API
================================================================================
Use this instead of the console for opt_in_keywords, opt_in_message, help_message
and opt_out_message. Those four have never once survived a console save.

Run it only AFTER the page changes are live at https://alexandergrant.app/sms.
Updating the campaign puts it straight back into carrier review, and a reviewer
opening the old form rejects again on the forced-consent note regardless of what

The script is committed at scripts/a2p-update.py. It parses the three message
strings out of src/lib/sms/auto-replies.ts rather than holding its own copies, so
what the campaign claims the number replies always equals what the number really
replies. Editing those constants and rerunning is the only supported way to
change them.

  python3 scripts/a2p-update.py --check     read the stored values, change nothing
  python3 scripts/a2p-update.py             write the four fields

--check needs no arguments and touches nothing, so run it first and last. It
reads TWILIO_ACCOUNT_SID and TWILIO_AUTH_TOKEN from the environment, falling back
to .env.local. The write path prints every value and waits for you to type "yes"
before sending, then reads the campaign back and marks anything still empty.
